## 2. 무엇을 만들고 있나

- 사람들이 많이 검색하는 것(MBTI, 룰렛, 사주, 꿈해몽, 계산기 등)을 **살짝 비틀어서** SEO로 일반 트래픽을 모으는 모바일 웹 도구 모음.
- 도메인 하나를 같이 쓰지만 **공통 홈·브랜드·사이트 이름은 없다.** 각 기능이 독립된 사이트처럼 따로 검색되고 방문된다.
  - 페이지 하단 "이것도 해보기" 링크 3개로만 서로 오간다 (그 링크도 각 사이트 장르의 물건 모양).
  - 루트 `/` 는 검색 제외(noindex) 단순 링크 목록일 뿐이다.

## 3. 사용자가 정한 절대 원칙 (반드시 지킬 것)

1. **항상 한국어로 대답한다.**
2. **AI티 안 나는 디자인이 최우선.** 사이트마다 실제 세계의 디자인 장르 하나를 골라 끝까지 민다. 웹디자인 레퍼런스 조사 후 반영.
3. **첫 화면은 반드시 쫄깃한 모션그래픽** — 그 기능이 실제로 움직이는 걸 보여줘서 바로 이해되게. 빈 공간 많은 화면 금지.
4. **모바일 최적화** (390px 기준, 가로 스크롤 없음).
5. **재방문·공유(확산)를 높이는 구조**가 핵심 아이디어여야 한다.
6. **모르는 사람과의 순위 경쟁 금지**, 지어낸 통계 금지 (사용자가 "전 국민 숫자 고르기" 같은 경쟁 아이디어를 명확히 거절함).
7. **기능 하나 = 페이지 하나.** 한 페이지에 여러 기능 몰아넣지 않기.
8. **허브/메인 페이지, 브랜드 이름 짓기 금지** ("놀이터", "심심상가" 같은 이름과 메인 페이지는 사용자가 거절함).
9. 디자인 시스템은 사용자가 준 레퍼런스대로: 색 역할 / 글자 역할(Display·Title·Body·Label·Caption) / 공통 컴포넌트와 상태 먼저 정의 / 간격 4·8·12·16·24·32 / Radius / Shadow S·M·L. "AI에게 만들게 하지 말고 고르게."

### 사용자가 "AI 같다"고 지적한 패턴 (다시 쓰면 안 됨)

- 작은 캡션 제목 + 회색 부제 + 꽉 찬 둥근 알약 버튼 + "~, 이렇게 ~해요" 굵은 소제목 + 회색 문단 조합
- 보라색 빛나는 구체, 그라디언트 글로우
- 모든 페이지에 똑같은 흰 카드 "이것도 해보기", 똑같은 "Q. 질문 ＋" FAQ
- 상단 경로 표시(빵부스러기), 카테고리 칩, 층별 상가 같은 공통 껍데기
- 시리즈 페이지가 서로 복제처럼 보이는 것
- 문구: "~에서 끝나지 않고", "~가 아니라 ~", "단순한 ~를 넘어"

자세한 규칙 전체: `docs/BUILD_GUIDE.md` (1~9장, 9장이 최신·최우선)

## 4. 구조

```
index.html              noindex 링크 목록 (브랜드·디자인 없음)
shared/tokens.css       디자인 토큰 (색 역할, 글자 역할, 간격, radius, shadow, 다크 테마, --ease-spring)
shared/components.css   공통 컴포넌트 (버튼·입력·카드·칩·시트·토스트·인트로·SEO 본문) 와 상태
shared/kit.js           공용 유틸 (아래 참고)
shared/sites.js         페이지 목록 TOOLS (하단 관련 링크·OG·사이트맵의 원본)
shared/vendor/lunar.js  음력·사주 계산 라이브러리 (사주·대운·손 없는 날)
test-kit/               심리테스트 공용 엔진 (engine.js, base.css)
<도구>/                  각 페이지 index.html, style.css, app.js, 데이터, og.png
scripts/                스크린샷, OG 이미지, 사이트맵, 도메인 교체, 꿈해몽 페이지 생성
docs/BUILD_GUIDE.md     제작 규칙
docs/HANDOFF.md         이 문서
```

### shared/kit.js 주요 함수

- 상태: `createStore`(localStorage), `encodeState`/`decodeState`(URL에 base64url JSON), `urlWith`, `getParam`
- 공유: `share`(Web Share 또는 복사), `shareImage(canvas, …)`, `downloadBlob`
- 매일 바뀌는 콘텐츠: `todayKey()`(KST), `dayNumber`, `seededRandom`(mulberry32), `hashString`, `shuffle`
- 화면: `runIntro({root, scenes, loop})`, `showView`, `openSheet`, `toast`, `haptic`, `countUp`, `prefersReducedMotion`, `sleep`, `$`, `$$`
- 캔버스: `createCanvas`, `roundRect`, `wrapText`, `CANVAS_FONT`
- 하단 관련 링크: `renderMoreSites(el, toolPath)` (같은 분류 2개 + 다른 분류 1개, 날짜별로 섞임). 마크업만 주고 모양은 각 사이트 CSS가 장르대로 입힘
- 페이지 이동 시 항상 맨 위에서 시작하도록 스크롤 리셋 (뒤로가기는 제외)
- `renderCrumb` 는 지금 아무것도 안 함 (경로 표시 제거됨)

## 6. 서버 없이 동작하는 방식

- 친구끼리 주고받는 데이터는 링크(URL)에 담고, 개인 기록은 브라우저(localStorage)에 저장.
- 카카오톡 인앱 브라우저와 크롬은 저장소가 따로라 기록이 나뉠 수 있음.
- 어디가? 의 실제 가게 정보: `where-to-go/config.js` 에 카카오 JavaScript 키를 넣으면 카카오 장소 검색, 없으면 OpenStreetMap(Overpass) → 내장 메뉴 목록.

## 7. 배포

정적 호스팅 (Vercel, Netlify, Cloudflare Pages, GitHub Pages). 빌드 명령 없음, 출력 폴더는 루트.

```bash
node scripts/set-domain.mjs https://내도메인.com   # canonical·sitemap 의 example.com 교체
node scripts/build-sitemap.mjs                      # sitemap.xml, robots.txt (현재 79개 URL)
node scripts/build-og.mjs                           # 없는 og.png 생성 (--force 로 전부 다시)
node scripts/build-dream-pages.mjs                  # 꿈해몽 사전 페이지 재생성
```

배포 후 구글 서치콘솔·네이버 서치어드바이저에 `sitemap.xml` 등록.

## 9. 남은 일 / 알려진 약점

- 2048 첫 화면 데모가 타일이 구석에 몰려 6~7개만 보임.
- 제비뽑기 SEO 본문에 회색 문단 하나 남아 있음.
- 추억 연대기(VHS) 릴이 일정한 속도로만 돎 (기계적인 회전).
- 샌드박스에서 웹 글꼴이 막혀 스크린샷은 대체 글꼴로만 확인함 → 실제 기기 확인 필요.
- 아직 main 브랜치에 합치지 않음, 실제 도메인 미정 (`site.config.json` 은 example.com).

## 10. 사용자 결정 대기 중인 아이디어 (확인 전에는 만들지 말 것)

- **같이 하는 심리테스트 5종:** 단톡방 캐릭터 도감 / 나 맞히기 퀴즈 / 우리 중에 누가? / 우리 사이 궁합 / 좀비 사태 생존 역할
- **미니게임 4종:** 맞춤법 퀴즈 / 떡 합치기 / 반응속도 결투 / 화투 짝 맞추기
- **단톡방 관계도:** 카카오톡 대화 내보내기 파일을 올리면 관계도를 그려줌. 1단계는 API 없이 브라우저에서 분석. 사용자의 익명화된 샘플 파일이 필요. AI 요약을 붙이려면 Claude API + 키를 숨길 백엔드 프록시 필요.
- **친구 결과 자동 집계:** Supabase 같은 DB 연결.
- 기타 후보: N빵 정산기, 전역일 계산기, 오늘의 타로.
- 제외 확정: 커플 디데이 ("아무도 안 쓸 것 같다"), 모르는 사람과 숫자 경쟁 게임.
