## 1. 목표

- 여러 브랜드 × 여러 판매법인 × 여러 채널을 운영하는 회사(IBR)의 **커머스 마스터 데이터 표준화·정규화** (구글시트).
- 목적: 사방넷 매핑을 체계적으로 다시 잡고, 상품 등록·가격 변경을 쉽게.
- 그 시트를 DB로 쓰는 **브랜드 운영 콘솔**: 결산·정산·일정·업무분배·담당자·브랜드에셋. 성격은 "브랜드가 들어오면 그대로 따라 하면 되는 워크플로우 기반 업무 길라잡이 + 체크리스트". 전사가 브랜드 내용을 같이 보고 같은 방향으로 가게.
- 최근 요청: 브랜드별로 **어디서·얼마에·어떤 형식으로 파는지**, **어떤 광고를 어느 스토어로 연결해 언제부터 언제까지 하는지**를 한 화면에서 관리 → 콘솔 "브랜드" 허브로 구현함.

## 2. 사용자와 합의한 원칙 (위반 금지)

1. **시트 안에 설명·주석 문구 넣지 않기.** 대신 드롭다운, 자동계산, 경고색, 필터로 사용성 확보.
2. **가격은 채널별이 아니라 가격정책 × 구성(판매구성)으로** 정한다. 가격정책: 소비자가격, 상시할인가, 브랜드위크가, 원데이특가, 모바일라이브방송가, 공동구매가, 폐쇄몰가격, 오프라인가격, 홈쇼핑가.
3. **공급가 = 판매가 − (판매가 − 원가) × 배분율** (기본 50%, 거래방식별 마진배분율 가능).
4. **판매채널은 말 그대로 채널**(스마트스토어, 쿠팡…). 다음은 채널이 아니다:
   - **라이브·공동구매·브랜드위크 등 = 판매형태** (판매형태 탭). 예: 네이버쇼핑라이브 = 스마트스토어 + 판매형태 라이브.
   - **도매·총판·특판·위탁·직매입·로켓그로스·공구 = 거래방식** (거래방식 탭). 대리점=도매, 기업특판=특판.
   - 단, **그립·클릭메이트는 판매채널**(사용자가 지정). **쓰리백 = 라이브 진행자**.
5. **공구 진행자·라이브 진행자 = 진행자** (진행자 탭). 유통사·대리점·총판 상대 = **거래처** (거래처 탭).
6. **수수료는 판매채널 + 거래처 + 진행자 + 거래방식 조합마다**(+적용시작일) 정한다. ("진"=진행자)
7. **웬만한 값은 다 가변**: 고정비는 월별 행, 수수료·비용은 적용시작일(·종료일)로 관리.
8. 같은 이름 채널이 온·오프라인, 홈쇼핑 TV/모바일로 갈리는 경우가 있음. 표기 없는 "현대홈쇼핑" = Hmall(모바일).
9. 상태값은 4개로 통일: **운영중 / 판매중단 / 운영중단 / 시작전**.
10. 매출 인식은 전 채널 판매가 기준. B2B는 공급가 정책을 판매가로. 로켓그로스는 밀크런배송비·보관료 차감.
11. 자사몰(카페24·식스샵·슈플마켓)은 PG 정산서에서 매출, 채널 정산서가 있는 채널의 PG 자료는 대사용.
12. TV 홈쇼핑은 별도 홈쇼핑 콘솔에서 관리(결산 포함 여부는 미정).
13. **보안: 비밀번호·인증정보는 절대 시트·문서·카톡에 옮기지 않는다.** (카톡 원문, 온라인팀 콘솔 시트의 정산계정PW/인증정보 열, 정산계정ID·CF/MID 포함). "비밀번호는 BM 콘솔에만 입력".
14. 역할 분담(사용자 동의): 마스터 시트 = 원장 / 대표의 BM 콘솔(ibr-online-console.netlify.app) = 계정 보관·정산 수집 / 이 콘솔 = 브랜드북·체크리스트·결산 뷰·브랜드 관리.
15. 자사 브랜드가 아닌 것(아리얼, 우불식당)은 결산에서 제외(브랜드 탭 상태=제외).

### 3-2. 수식·도구 메모
- SUMIFS는 ARRAYFORMULA 안에서 안 펼쳐짐 → `SUMIF(키&"|"&키, …)` 또는 MAP/BYROW 사용.
- 조건부서식에서 다른 시트 참조는 `INDIRECT("'탭'!A:A")`로만 가능. **열을 삽입해도 INDIRECT 문자열은 안 바뀜** → 열 삽입 후 반드시 점검.
- BYROW/MAP 안의 배열 연산은 `ARRAYFORMULA(...)`로 감싸야 함.
- IMPORTRANGE는 10MB 한도 → 필요한 열만 가져와서 `{}`로 합침.
- batchUpdate 필드 마스크는 괄호 말고 쉼표 경로(`userEnteredFormat.backgroundColor,...`).
- USER_ENTERED라 앞자리 0 코드는 TEXT 서식 먼저.

## 8. 진행 중이던 작업 (여기서부터 이어가기)

**비용 통합** — 사용자 "뭐 해봐"로 승인받고 진행하다 중단됨.
1. ✅ `비용` 탭 생성·서식·드롭다운·경고색.
2. ✅ `채널옵션` V 추가비용 / W 예상공헌이익 자동열 (테스트 통과: 스마트스토어 3,000 / Hmall 위탁 3,750 / 직매입 0).
3. ⏳ `비용대사` 탭: 데이터·수식은 들어갔고 값 정상. **남은 것**:
   - 헤더 서식, 필터, E·F·J·K 천단위 서식, G·H·I 퍼센트 서식, E~K 회색+보호
   - B 판매채널 / C 거래방식 / D 진행자 드롭다운
   - 경고색: |I|≥5%p 빨강, B 비어있으면 노랑, H 비어있으면(마스터 수수료 없음) 노랑
4. ⏳ 비용대사에서 드러난 큰 차이 → 사용자에게 어느 값이 맞는지 확인 후 수수료 탭 수정:
   - 쿠팡 실측 10.6% vs 마스터 40%(위탁·로켓그로스·직매입 모두 30~40%로 들어가 있음, 직매입 실측 0%)
   - CJ온스타일·현대홈쇼핑·Hmall 실측 20% vs 마스터 30%
   - 신세계몰 19% vs 30%, SSG 19% vs 9%, 톡스토어 21% vs 10%, 식스샵 7% vs 4%
   - **카페24 자사몰 실측 100%** (스킬 수수료표 누락으로 보임; 식스샵 일부 브랜드 과거 월도 100%)
5. ⏳ 사방넷 수집 스킬 수정: 사용자 Claude에 있음. 사용자가 SKILL.md/스크립트를 업로드하거나 조직 스킬로 공유하면 → 수수료·배송비를 마스터 `수수료`·`비용` 탭에서 읽게 수정.
6. 이후: 콘솔 결산에 "예상 대비 실제 비용 차이" 경고 추가.

## 9. 사용자 확인 대기 질문

- 채널옵션 라메종드미엘 2행의 스토어

## 10. 사용자 할 일 (안내했던 것)

1. 콘솔 열고 Google Sheets 허용 → 실제 데이터로 화면 확인
2. 담당자 탭 채우기 (체크리스트 자동 배정·"나" 선택용)
3. 채널옵션 빨간 2행 스토어 지정
4. 브랜드별 판매 옵션 등록(콘솔 → 브랜드 → 판매 → "이 스토어에 옵션 추가")
5. 스토어 탭 E열 사방넷 쇼핑몰ID (스토어 단위 실적용)
6. 브랜드북 작성, 광고 기간·월예산 입력
7. 콘솔을 팀과 쓰려면 콘솔 공유 메뉴에서 권한 부여
8. 최종 목적지: 채널옵션이 채워지면 사방넷 매핑 스킬(`sabangnet-mapping`)로 품번·단품 매핑
